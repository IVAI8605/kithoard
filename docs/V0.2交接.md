## 本批刻意没做的（后续补）

1. **拖拽移动**：§7.4-12 的「拖拽移动」未做。应用内没有目录树，拖到资源管理器的语义（复制还是移动）由 Windows 决定，跨应用拖拽也不可控，先只提供「移动到…」选择框（见待定问题 19）。
2. **预览**：§7.4-12 的「预览」当前等同于「用系统默认程序打开」，应用内不做播放器；如需内嵌预览，等 V0.4 图片处理时一并评估。
3. **真实 GUI 端到端**：已完成（见上节「真机验收」）；原生目录选择框、并发压测、界面第 21 个勾选提示仍未覆盖。
4. `download:estimate` 通道已实现（第七批），批量确认框会显示数量与预计大小；单条快速下载仍不弹确认。
5. 真实 v2 → v3 迁移冒烟已跑（第七批，一次性脚本在 `cache/verify/`），结果 PASS。
6. 模板类型下载：当前一律拒绝，等出现真实来源再定白名单。
7. 图片 CDN 忽略 `Range`，图片续传退化为全量重下；视频 CDN 已实测支持 206 续传（见待定问题 18）。
8. **启动全量对账**：按待定问题 16 的默认项，只在拉取列表时按页核对，不在启动时全量 stat。

## 下一批建议（恢复开发时先看这里）

1. **V0.2 已具备收口条件**：代码、门禁、真机验收均通过。建议先由用户决定是否收口进 V0.3，不要自行发版、打 tag 或打包。
2. 若要继续打磨 V0.2：原生目录选择框交互、并发 1–5 压测、界面第 21 个勾选提示、缺失行属性按钮禁用，这四项都是小改动。
3. 如果拖拽移动仍需保留，先补一份「拖到应用内目录树」的设计（不做跨应用拖拽），再单独排期。
4. V0.3 范围（收藏夹/设置/Pexels/备份）按 `版本规划.md` §7.5 执行；发版相关动作需用户点头。
