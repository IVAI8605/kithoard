## 本批刻意没做的（下一批补）

1. 不建 `.part`：规划和引擎一起落，见 `cache/待定问题.md` 第 6 条。
2. 取消不删 `.part`：引擎批次按 §5.8 处理（应用临时文件允许物理删除）。
3. 排队任务不能暂停：`queued → paused` 不在 §5.3 表里，见 `cache/待定问题.md` 第 5 条。
4. 无 UI、无 `download:list` / `resume` / `retry` / `reorder` / 进度事件。

## 下一批建议：下载引擎（§7.4-1/3/4）

- 队列调度与并发槽位 1–5（`download.concurrency`，默认 3；调小不抢占在跑任务）。
- `.part` 增量写入 + Range + `ETag`/`Last-Modified` + §5.5 八个服务器分支。
- 进度 500 ms 合并推送；`received_bytes` 落库按 §5.6（状态迁移、暂停、取消、每 5 秒或每 8 MB）。
- 新增 `download:list`、`download:resume`、`download:retry`、`download:reorder` 与 `download:progress` / `download:state` 事件。
- 引擎测试：Range 分支与恢复表优先做纯函数，再挂 IPC。
