## 本批刻意没做的（下一批补）

1. **启动恢复接线**：§5.4 决策函数已就绪，但启动时没有扫描与「是否恢复」弹窗（§7.4-9）。
2. **下载管理页与卡片快速下载**：界面仍置灰（§7.4-7/8/14）。
3. `download:estimate` 通道、批量确认框、大文件 `confirmLarge` 的真实弹窗（§7.4-8）。
4. 隔离区界面：通道已具备，但没有页面入口。
5. 模板类型下载：当前一律拒绝，等出现真实来源再定白名单。

## 下一批建议：下载管理页 + 启动恢复

- 左侧「下载管理」解除置灰：列表、进度、暂停/继续/取消/重试、拖拽排序接现有通道。
- 启动时按 §5.4 扫描 `downloading/paused/verifying/quarantined` 记录，弹窗询问是否恢复；`queued` 不自动开始。
- 隔离区入口：列表、恢复、放弃（回收站）。
- 卡片「快速下载」与批量入队确认；大文件走 `confirmLarge`。
- 单测优先：队列排序/状态展示映射、恢复弹窗决策；界面用真实 Pixabay 素材做一次端到端。

## 环境与红线

- 仓库 `https://github.com/IVAI8605/kithoard`，main 分支；每批过门禁后自行 commit + push，不打 tag、不建 Release、不打包。
- Pixabay Key 只在 `cache/.pixabay-key` 与应用设置里，绝不提交、不写进文档和日志。
- 不永久删除文件；`.part` / `cache` 属 §5.8 已知例外。
- 每批改动前备份到 `cache/backup/`，验证单写 `cache/验证单/v0.2.0.md`（都不进仓库）。
