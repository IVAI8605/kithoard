### V0.3 第四批：备份导出与导入

| 项 | 落点 |
|---|---|
| 备份格式 | `src/main/backup/format.ts`：`schemaVersion=1`，含 assets / favorites / downloads / localFiles / settings；收藏与下载只记 `(sourceId, remoteId)`，不信任本地自增 id |
| 导出 | `src/main/backup/index.ts` 的 `buildBackup`：只读库；settings 只导出 `source.enabled` / `download.dir` / `download.concurrency`，`source.apiKey.*` 永不出现 |
| 导入 | `restoreBackup`：事务内按 §5.7 顺序执行——upsert 素材并建 ID 映射 → 重建收藏 → 下载记录按 `target_path` 去重 → 本地文件按磁盘存在性标 `present` / `missing`；非终态下载统一置 `paused` |
| 校验 | `parseBackupJson` 在写库前完成；非法 JSON、缺 `schemaVersion`、高版本、字段类型错误一律 `E_RESTORE_INVALID`，库不变 |
| 入口 | `settings:backup` / `settings:restore`；设置页「备份与恢复」支持导出、导入（二次确认）、导入摘要与界面刷新 |
| 单测 | `test/backup.test.ts`（11 例：Key 剔除、导出映射、ID 重映射、路径缺失、未完成任务降级、id 冲突、重复导入、白名单、非法文件） |

**门禁**：六关全 PASS（166 个单测）。

## 未验证项与待定（V0 收口）

| 项 | 原因 | 默认选择 / 后续 |
|---|---|---|
| **卸载时「同时删除我下载的素材」**（`cache/待定问题.md` 第 20 条） | 自动删除用户文件属破坏性操作；开发机是日常在用机器，无干净环境做安装-卸载验证，写错脚本会误删真实素材 | V0.6 卸载**默认保留**数据库、设置与全部已下载素材，不提供自动删除；用户可在本地素材页逐条删除到回收站。有干净测试机后再实现「导出清单 → 校验路径 → 二次确认」，并满足 §7.8-6 三条硬边界（清单只来自 `local_files`、盘符根/系统目录拒绝、提权前后都可见） |
| 安装/卸载全流程 | 无干净 Windows 环境 | 标准 NSIS 模板生成，配置已核对；有干净机后按 §7.8-验收 5 补跑 |
| Pexels 真实 Key 搜索/下载 | 只有 Pixabay Key | 端点与清晰度选择有单测，低风险；有 Key 后补冒烟 |
| 导入对话框「打开」按钮 | 原生对话框无法由 CDP/PowerShell 稳定触发 | 已用真实备份文件对真实库完成导入验证（见 `cache/验证单/v0.3.0.md` R12/R13）；手动点一次即可闭环 |
| 「全程不切窗口」单次连续演示 | 各能力分别验证，未一次连续点击串起来 | V1.0 回归时补一次连续演示 |
| 大库 1 万条性能 | 决策 D13 定规模，合格线仍标【未验证】 | 按 D13 在目标机实测后回填，不编数字 |

**实现口径说明（非未验证项）**：

## 环境与红线

- 仓库 `https://github.com/IVAI8605/kithoard`，main 分支；每批过门禁后提交推送。
- 发版、打 tag、打包按用户授权执行；V0.3.0 / 0.4.0 / 0.5.0 / 0.6.0 均已发布，`v0.6.0` 为 Latest。
- Pixabay Key 只在 `cache/.pixabay-key` 与应用设置里，绝不提交、不写进文档和日志。
- 不永久删除文件；`.part` / `cache` 属已知例外。损坏数据库改名留档，不物理删除。
- 每批改动前备份到 `cache/backup/`，验证单写 `cache/验证单/`（不进仓库）。
- 仓库未配置 GitHub Actions（工程规范 §9 明确暂不建 CI）；产物由本机打包、验证后上传 Release。
