## 已完成批次

### V0.3 第一批：收藏夹

| 项 | 落点 |
|---|---|
| 数据表 | `src/main/db/migrations.ts` 新增 v4 `favorites`；素材外键 CASCADE，`UNIQUE(asset_id)`；`user_version` 升到 4 |
| 收藏 service | `src/main/services/favorite.ts`：`toggle` / `add` / `remove` / `list` / `ids`；收藏前校验素材存在，避免外键原始错误冒到界面 |
| 通道 | `favorite:toggle` / `add` / `remove` / `list` / `ids`，preload 白名单同步 |
| 渲染层 | `FavoritesPage`（筛选、分页、全选、批量取消、查看详情、空态）；`AssetCard` 增加收藏按钮；`DetailView` 启用下载与收藏；`Sidebar` 解禁收藏夹，版本号 V0.3 |
| 状态联动 | `store.favoriteIds` 全局维护，收藏/取消后统一刷新；卡片与详情页共用 |
| 单测 | `test/favorite.test.ts`（7 例：toggle、批量增删、去重、参数边界） |

**门禁**：六关全 PASS（146 个单测）。

### V0.3 第二批：设置页与缓存清理

| 项 | 落点 |
|---|---|
| 设置白名单 | `READABLE_SETTINGS` 增加 `download.dir` / `download.concurrency` / `cache.size`；`WRITABLE_SETTINGS` 增加前两项 |
| 设置 service | `services/settings.ts`：目录复用 `assertMovableDir` 白名单校验；并发必须是 1–5 整数，保存后调用 `engine.pump()` 立即生效；新增 `pickDir` 与 `cleanCache` |
| 缓存 | `src/main/cache/clean.ts`：只清 `cache/thumbs` 与 `cache/http` 中超过 7 天的文件，跳过 `.part`；提供 `cacheSize` 统计 |
| 启动清理 | `registerIpc` 启动时执行一次，清理结果写日志 |
| 页面 | `SettingsPage`：保存目录、并发数、缓存占用与清理、源开关、Key 配置；`Sidebar` 解禁「设置」 |
| 单测 | `test/cache-clean.test.ts`（5 例：过期清理、`.part` 保护、未知目录不动、占用统计、目录缺失） |

**门禁**：六关全 PASS（151 个单测）。

### V0.3 第三批：Pexels 第二个源与按源分组

| 项 | 落点 |
|---|---|
| Pexels 适配器 | `src/main/sources/pexels.ts`：图片 `/v1/search`、视频 `/videos/search`，Key 走 `Authorization` 头；视频优先 1280–1920 mp4；许可统一 `free` |
| HTTP | `fetchJson` 支持自定义 headers，并把 headers 计入缓存 key，避免不同 Key 命中同一份响应 |
| 注册与限流 | `sources/index.ts` 注册 Pexels，3 次/分钟（官方 200 次/小时） |
| 分组搜索 | `services/search.ts` 抽出 `runOne`；新增 `searchGrouped`（并行、单源失败隔离）与 `searchSource`（组内翻页只请求该源） |
| 配置 | `READABLE/WRITABLE_SETTINGS` 增加 `source.apiKey.pexels`；设置页按来源渲染开关与 Key |
| 渲染层 | `store.groups` 取代单一 `items/result/page`；搜索页按来源分组、组内独立翻页；`saveApiKey(sourceId, key)` |
| 单测 | `test/pexels.test.ts`（4 例：端点与参数、清晰度选择、兜底、空列表） |

**门禁**：六关全 PASS（155 个单测）。

**未验证**：Pexels 真实接口需要 Pexels Key，当前只有 Pixabay Key，真实搜索与下载未跑（见验证单）。

### V0.3 第四批：备份导出与导入

| 项 | 落点 |
|---|---|
| 备份格式 | `src/main/backup/format.ts`：`schemaVersion=1`，含 assets / favorites / downloads / localFiles / settings；收藏与下载只记 `(sourceId, remoteId)`，不信任本地自增 id |
| 导出 | `src/main/backup/index.ts` 的 `buildBackup`：只读库；settings 只导出 `source.enabled` / `download.dir` / `download.concurrency`，`source.apiKey.*` 永不出现 |
| 导入 | `restoreBackup`：事务内按 §5.7 顺序执行——upsert 素材并建 ID 映射 → 重建收藏 → 下载记录按 `target_path` 去重 → 本地文件按磁盘存在性标 `present` / `missing`；非终态下载统一置 `paused` |
| 校验 | `parseBackupJson` 在写库前完成；非法 JSON、缺 `schemaVersion`、高版本、字段类型错误一律 `E_RESTORE_INVALID`，库不变 |
| 入口 | `settings:backup` / `settings:restore`；设置页「备份与恢复」支持导出、导入（二次确认）、导入摘要与界面刷新 |
| 单测 | `test/backup.test.ts`（11 例：Key 剔除、导出映射、ID 重映射、路径缺失、未完成任务降级、id 冲突、重复导入、白名单、非法文件） |

**门禁**：六关全 PASS（166 个单测）。

### V0.3 第五批：清空数据

| 项 | 落点 |
|---|---|
| 范围 | `favorites` / `downloads` / `settings` / `all`；`all` 只合并三类，不删 `assets` 与 `local_files` |
| service | `src/main/services/reset.ts`：事务删记录；清下载历史前先 `engine.stop(cancel)` 活动任务并清理无主 `.part` |
| 外键 | 删除 `downloads` 时 `local_files.download_id` 由 `ON DELETE SET NULL` 自动置空，本地素材记录与磁盘文件都保留 |
| 入口 | `settings:clearData`；设置页「清空数据」按范围选择、二次确认，明确提示「素材文件不会被删除」与「设置含 API Key」 |
| 单测 | `test/reset.test.ts`（6 例：仅收藏、仅下载、仅设置、全部、活动任务停止与 `.part` 清理、非法范围） |

**门禁**：六关全 PASS（172 个单测）。
