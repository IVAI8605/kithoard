## 0. 术语约定

统一叫法，避免同一件事在不同文档里换名字。

| 术语 | 含义 |
|---|---|
| 素材源（Source） | 一个可检索的外部素材提供方，如 Pixabay、Pexels。每个源对应一个适配器实现 |
| 适配器（Adapter） | 把某个素材源的 HTTP 接口翻译成统一 `AssetSource` 接口的代码单元 |
| 素材（Asset） | 一条素材元数据记录，跨源唯一标识为 `source_id + remote_id` |
| 直链（Direct URL） | 可被浏览器或下载器直接 GET 到的文件地址，区别于需要登录/跳转的页面地址 |
| 落地（Land） | 素材从网络落到本地磁盘并被登记进本地素材库的完整过程 |
| 隔离区（Quarantine） | 被判定有风险的文件暂存目录，文件被移入而非删除，可人工恢复 |
| 占位（Placeholder） | 数据缺失时的空态展示。**与"假数据"严格区分**：占位必须显式标注"未知"，不得填造数值 |
| 门禁（Gate） | 每次改动后必须通过的自动化检查集合，见第 7.2 节 |

## 1. 产品目标与边界

### 1.1 一句话目标

给做视频剪辑和设计的人一个**本地素材中转站**：在软件里搜到合法可下载的素材，一键落到本地目录，之后能在这个软件里找到、预览、整理、做基础处理，不用在十个网站和三个文件夹之间来回切。

### 1.2 用户能感知到的成功标准

不谈功能清单，只谈"用户用完会不会留下"：

1. 搜一个词，**10 秒内**看到 20 条真实可用的结果，且能翻到第 2 页。
2. 点一下就能把一条素材存到本地，**知道它存在哪个文件夹**。
3. 下载到一半关软件，重开能接着下，不用从头再来。
4. 三个月后回来，**还能搜到自己下过的东西**，按类型分得清。
5. 转化/压缩完，**原文件还在或者被安全替换**，不会因为工具本身丢素材。

以上五条任何一条做不到，这一版就不算完成。

### 1.3 明确不做（非目标）

需求文档已经排除了一批，这里补上工程侧同样不该做的：

| 不做 | 原因 |
|---|---|
| 绕过登录、付费、会员、验证码、防盗链 | 需求红线，也是法律风险 |
| 爬取无官方 API 的站点页面来凑搜索结果 | 需求十.6 明确禁止伪造；且解析 DOM 极不稳定 |
| 自建素材网站 / 自建 CDN / 素材转售 | 不是这个产品 |
| 视频剪辑、时间线、多轨合成 | 需求五明确排除 |
| 图片去背景、加 AI 水印、AI 生成 | 需求五明确排除 |
| 云同步、账号体系、多端漫游 | 需求只要"备份文件 + 换机导入" |
| 开机自启、托盘常驻、窗口置顶、全屏 | 需求七明确排除 |
| 内置浏览器内核 / 自研渲染引擎 | 直接用系统 WebView2 或 Chromium |
| 素材去重算法做到感知哈希级别 | 需求只在第三阶段提"重复文件识别"，先按内容哈希做 |

### 1.4 与需求文档的映射

需求文档三段式优先级（核心 / 处理 / 稳定性）在工程上不能照搬，因为"断点续传"不是收尾工作，是下载器的**数据结构决定项**——先做不带续传的下载器，后面必然重写。映射关系：

| 需求文档阶段 | 本文对应 | 差异说明 |
|---|---|---|
| 第一阶段 核心软件 | V0.1.0 ~ V0.3.0 | 拆成三轮，每轮一个可验收闭环 |
| 第二阶段 素材处理 | V0.4.0、V0.5.0 | 图片与音视频分开，因为依赖不同（sharp vs FFmpeg） |
| 第三阶段 稳定性 | 前移到 V0.2.0 / V0.3.0 / V0.6.0 | 续传随下载器一起做；崩溃恢复随任务表一起做；安全隔离放 V0.6.0 |

### 1.5 首版范围（已冻结，2026-11-08）

这一版只做下面这些，超出范围的一律进 `版本规划.md` 的延后表：

| 维度 | 首版范围 | 不在首版 |
|---|---|---|
| 素材源 | Pixabay 单源 | Pexels（V0.3.0）、Unsplash、其它 |

## 2. 硬约束（每个提交都不许破）

### 2.1 数据诚实

这是需求文档反复强调、也最容易在赶进度时被破坏的一条。

- 搜索结果**只能来自真实 API 调用**。请求失败就是失败，展示"服务暂不可用"和重试按钮，不允许回退到本地假数据。
- 下载进度**只能来自实际写入字节数**，不允许用定时器模拟百分比。
- 文件大小、分辨率、时长，取不到就写 `NULL` 并在 UI 显示"未知"，**不允许填 0 或估算值**。
- 空态、加载态、错误态三种状态必须在 UI 上可区分，不允许用骨架屏长期伪装成有数据。

### 2.2 用户文件安全

- **替换原文件必须先落新文件再原子换名**：写 `目标.tmp` → 校验成功 → `rename` 覆盖。校验失败删 `tmp`，原文件一字不动。
- **删除一律走回收站**（`shell.trashItem`），不做 `unlink` 式物理删除。批量删除必须二次确认并列出文件名。
- **写入任何用户目录之前先检查可写性**，不可写就报错并让用户改目录，不允许静默失败。
- 下载中的临时文件用 `.part` 后缀，**不占用目标文件名**，避免用户看到半截文件。

### 2.3 合规

- 每个素材源适配器必须声明 `attributionRequired`，由 UI 强制展示署名，不允许适配器"忘记"。
- **署名分两处呈现**（2026-11-08 定案，见 8.1）：卡片底部一行 11px 灰字；详情页完整署名（作者名 + 来源站名 + 回链，回链按源的要求带 `utm` 参数）。素材卡片**仍不显示来源网站图标和名称**，这是两条不同的事，不要混为一谈。
- **`attributionRequired` 为接入 Unsplash / Pexels 的前置条件**：首版只接 Pixabay（其 License 不强制署名），但 `assets` 表的 `author_name` / `author_url`、适配器的 `attributionOf()`、卡片的署名插槽必须在 V0.1.0 就建成，否则将来接强制署名的源要动卡片布局和表结构。**字段先有、数据可空、UI 按 `attributionRequired` 决定是否渲染**。
- 许可状态未知（`license = unknown`）的素材，详情页醒目提示且**禁用下载按钮**。
- 每次下载前记录来源页面 URL，写入数据库，便于追溯。
- 第三方组件（FFmpeg、sharp、Electron）的许可证必须落 `THIRD_PARTY_NOTICES.md`。

### 2.4 平台

- 只支持 Windows 10 1809+ / Windows 11（x64）。不做 ARM64、不做 macOS/Linux。
- 界面全简体中文，不引入 i18n 框架（需求只要中文，过早国际化是浪费）。
- 不使用需要管理员权限的运行时操作。

## 3. 技术选型

### 3.1 结论

| 层 | 选定 | 备注 |
|---|---|---|
| 桌面框架 | **Electron**（最新稳定版） | 理由见 3.3 |
| 前端 | React + TypeScript + Vite | 需求文档硬约束，照办 |
| 构建 | electron-vite | 一份配置同时管 main / preload / renderer |
| 状态管理 | Zustand | 比 Redux 轻，比 Context 好调试 |
| UI 基础 | 自建 CSS 变量 + 少量无样式组件 | 不引重型 UI 库，避免和"简洁不堆砌"冲突 |
| 数据库 | SQLite（`better-sqlite3`） | 需求硬约束 SQLite；同步 API 适合主进程 |
| 图片处理 | `sharp` | 原生模块，需 `asarUnpack` |
| 音视频处理 | FFmpeg 可执行文件（sidecar） | 用 7.x，不用本机老版本 |
| 打包 | `electron-builder` + NSIS | 支持安装目录自选 |
| IPC | `ipcMain.handle` / `ipcRenderer.invoke` | 全量走 request/response，事件单独走 send |

### 3.2 决策矩阵

权重按本项目的实际痛点排，不是通用排名。

| 维度 | 权重 | Electron | Tauri 2 | 判定 |
|---|---|---|---|---|
| 窗口内嵌第三方网站 | 高 | `WebContentsView` 官方稳定 API | 同窗口多 webview 需 `unstable` feature | **Electron 胜** |
| 本机工具链就绪度 | 高 | Node 已装，可直接开工 | 需装 rustup + MSVC Build Tools（数 GB） | **Electron 胜** |
| 断点续传可控性 | 高 | Node `http` + `Range` 完全自控 | 需引第三方插件或用 Rust 自写 | 平 |
| 安装包体积 | 低 | 约 100–150MB | 约 10–20MB | Tauri 胜，但本项目无体积指标 |
| 空载内存 | 中 | 约 200–300MB | 约 60–100MB | Tauri 胜，但素材工具用户通常常驻大型软件 |
| 原生模块/FFmpeg 集成 | 中 | `child_process` 直连 | sidecar，需配置 | 平 |
| 团队/后续维护成本 | 中 | TS 单一语言栈 | 需同时维护 Rust + TS | **Electron 胜** |

### 3.3 选型理由

**第一条，也是决定性的：内嵌浏览是需求硬项，Tauri 在这个点上用的是不稳定 API。**

需求文档二.2 要求"支持在软件内部浏览素材网站"。Electron 官方文档明确把 `WebContentsView` 作为在 `BaseWindow` 内组合多个页面的推荐方式（`<webview>` 标签被标注为不保证长期支持，所以不用它）。而 Tauri 2 官方文档在 child webview 一节写明：在一个窗口内通过 `new Webview(...)` 创建多个 webview **属于 unstable API**，必须给 `tauri` crate 打开 `unstable` feature（`Window::add_child`）。把核心功能压在一个被官方标注 unstable 的接口上，升级风险不可控。

**第二条：本机环境实测决定了开工路径。**

实测结果（2026-11-08，本机 Windows 11 26200）：

| 检查项 | 结果 |
|---|---|
| Node.js | v24.22.1 ✅ |
| npm | 11.19.1 ✅ |
| WebView2 Runtime | 157.0.4341.42 ✅ |
| FFmpeg | n4.4.1（2022-01-22 构建）⚠️ 偏旧 |
| Python | 3.12.10 ✅ |
| git | 2.56.0 ✅ |
| Rust / cargo | **未安装** ❌ |
| MSVC Build Tools | **未检测到** ❌ |

走 Tauri 需先补 rustup + VS Build Tools C++ 工作负载，装完再等首次编译。"第一版要在真机上跑通完整链路"这个目标下，这条路径明显更长。走 Electron 则是 `npm install` 之后就能起窗口。

**第三条：下载器的可控性。**

需求要求真实进度、真实暂停、真实续传、并发 1–5、重启恢复。这些用 Node 原生 `http/https` + `Range` 请求自己实现（约 300 行），逻辑完全透明，出错好定位。引第三方下载库反而要迁就它的状态机。

**代价，说清楚**：安装包 100MB 级别，空载内存 200–300MB。需求文档没有给体积和内存指标，且目标用户本身常驻 Premiere、Photoshop 这类软件，这个量级可接受。

### 3.4 依赖清单与引入纪律

| 包 | 用途 | 引入阶段 |
|---|---|---|
| `electron` | 运行时 | V0.1.0 |
| `electron-vite` / `vite` | 构建 | V0.1.0 |
| `react` / `react-dom` | UI | V0.1.0 |
| `typescript` | 类型 | V0.1.0 |
| `zustand` | 渲染进程状态 | V0.1.0 |
| `better-sqlite3` | 数据库 | V0.1.0 |
| `electron-builder` | 打包 | V0.1.0（先能出免安装版即可） |
| `sharp` | 图片处理 | V0.4.0 |
| `ffmpeg` 二进制 | 音视频 | V0.5.0 |
| `vitest` | 单测 | V0.1.0 |
| `playwright` | 端到端冒烟 | V0.2.0 |

纪律：

1. **每个依赖都要能说出替代方案和为什么不用**。说不出就先不引。
2. 原生模块（`better-sqlite3`、`sharp`）必须走 `electron-builder` 的 `npmRebuild`，并在 `asarUnpack` 里排除，否则打包后必崩——这是 Electron 最常见的发布事故。
3. 不加 UI 组件库、不加 CSS 框架、不加图标字体包。图标用内联 SVG。
4. 版本锁定写死在 `package.json`，不用 `^`，避免某次 `npm i` 后行为漂移。

### 3.5 开工前必须补齐的环境缺口

| 缺口 | 处理 | 时机 |
|---|---|---|
| FFmpeg 4.4.1 偏旧（2022 年构建） | 下载 FFmpeg 7.x static build，放 `resources/bin/`，**不依赖系统 PATH** | V0.5.0 前 |
| 无 Rust / MSVC | 走 Electron 路线则不需要 | — |
| 无 pnpm | 用 npm 即可，不额外装 | — |

FFmpeg 必须随包分发而不是依赖系统安装，否则用户机器上必然出现"换台电脑就转不了码"。**该方案已于 2026-11-08 定案：接受安装包因此增加约 80 MB**（见第 8 节汇总表第 7 条）。

### 3.6 回退方案

如果后续实测发现内存/体积不可接受（例如目标机器是 4GB 内存老笔记本），迁移路径是：

- 渲染层（React + TS）可整体复用；
- 主进程的 `sources/`、`download/`、`db/`、`media/` 是纯 TS 逻辑，可平移到 Node 侧或改写为 Rust；
- **唯一需要重写的是"内嵌浏览"模块**（`WebContentsView` → Tauri child webview）。

所以架构上要求：**内嵌浏览必须是一个独立、可整体替换的模块**，不允许把浏览器逻辑散落到搜索页、详情页里。见 4.3 节的模块边界。

## 4. 架构与模块划分

### 4.1 进程模型

```
┌──────────────────────────── 主进程（Node，有全部权限） ────────────────────────────┐
│  db/         SQLite 唯一写入者                                                   │
│  sources/    素材源适配器（HTTP 调用、限流、缓存）                                 │
│  download/   下载引擎（队列、并发、续传）                                          │
│  library/    本地素材扫描与管理                                                   │
│  media/      图片/音视频处理（调 sharp / ffmpeg）                                  │
│  safety/     文件风险检查与隔离区                                                  │
│  ipc/        通道注册，统一错误信封                                                │
└───────────────────────────────────────────────────────────────────────────────┘
        ▲ invoke（请求/响应）                    ▲ webContents.send（进度等事件）
        │                                        │
┌───────┴────────────────────────────────────────┴──────────────────────────────┐
│  preload（contextBridge，白名单暴露，无 Node 权限）                              │
└───────┬───────────────────────────────────────────────────────────────────────┘
        │
┌───────┴──────── 渲染进程（React，contextIsolation 开启，nodeIntegration 关闭）────┐
│  pages/      首页搜索、网站导航、收藏夹、下载管理、本地素材、设置                 │
│  components/ 卡片、分页、右键菜单、批量操作条、预览器                             │
│  stores/     Zustand                                                          │
└───────────────────────────────────────────────────────────────────────────────┘
```

安全基线（不满足就不算能发版）：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、preload 只暴露明确列出的方法、主进程校验所有入参。

**分层纪律**：`shared/` 不引 Node 模块；`renderer/` 不直接 `require`；主进程模块之间**只通过函数调用，不互相 import IPC**。

### 4.3 模块职责边界

| 模块 | 负责 | 不负责 | 关键约束 |
|---|---|---|---|
| `sources` | HTTP 请求、响应映射、限流、署名信息 | 不碰数据库、不碰磁盘 | 纯函数式：输入查询，输出 `AssetMeta[]` |
| `db` | 建表、迁移、事务 | 不含业务判断 | 全应用**唯一**写库入口 |
| `download` | 队列、并发、续传、校验 | 不决定存哪（由设置给） | 状态迁移必须过状态机，禁止直接改字段 |
| `library` | 列表、搜索、改名、删除、移动 | 不做格式转换 | 所有删除走回收站 |
| `media` | 调 sharp / ffmpeg，产出新文件 | 不自动替换原文件 | 替换逻辑由调用方在成功后执行 |
| `safety` | 风险判定、移入隔离区 | 不替代 Windows Defender | 判定结果必须给出可读原因 |
| `browser` | 内嵌页面、地址栏、复制链接 | 不做页面内容解析 | 与搜索/详情**零耦合**，便于整体替换 |
| `backup` | 导出/导入 JSON | 不含下载的素材文件 | 只备份"数据"，素材靠用户自己拷 |

### 4.4 两条主数据流

**搜索一次**：

```
用户在首页输入关键词
 → renderer 调 search:run({keyword, type, page:1})
 → ipc/guard 校验参数
 → sources/registry 取启用的源（首版 1~2 个）
 → 各源并行发请求（http.ts 统一超时 12s、429 指数退避、24h 响应缓存）
 → 归一化为 AssetMeta[]，写入 assets 表（upsert）
 → 取每源前 20 条合并 → 分页切片
 → 返回 SearchPage 给渲染进程 → 渲染卡片
```

失败时不返回空数组冒充成功，直接抛 `AppError`，UI 显示"该来源暂不可用 + 重试"。

**下载一次**：

```
用户点快速下载 / 批量下载
 → 若批量：先汇总 {files: n, estimatedBytes: n} 让用户确认
 → download:enqueue([assetId...])
 → 主进程：查 assets 拿直链 → 解析文件名与扩展名 → 检查目标目录可写
          → 中文名/非法字符/重名冲突处理 → 建 .part 与 .part.meta
          → 写 downloads 表（state=queued）
 → engine 按并发槽位取任务 → state=downloading
 → HTTP Range 请求，分块写盘，每 500ms 累加 received_bytes 并发下载进度事件
 → 完成 → state=verifying → 校验大小与魔数 → state=completed
 → 登记 local_files 表 → 发 finished 事件给 UI（提供"打开文件/打开文件夹"）
```

## 5. 数据与状态设计

### 5.1 数据落地位置

| 内容 | 位置 | 说明 |
|---|---|---|
| SQLite 主库 | `%APPDATA%/Kithoard/kithoard.db` | Electron `app.getPath('userData')` |
| 缩略图与预览缓存 | `%APPDATA%/Kithoard/cache/` | 可整目录删除，7 天清理的对象 |
| 隔离区 | `%APPDATA%/Kithoard/quarantine/` | 只移入不删除 |
| 诊断日志 | `%APPDATA%/Kithoard/logs/` | 轮转：单文件 2 MB × 3 份，**无 UI 入口**（见 8.5） |
| 下载素材 | 用户设置，默认 `%USERPROFILE%/Pictures/Kithoard` | **在 userData 之外**，卸载不连带 |
| 下载临时文件 | 与目标文件同目录的 `xxx.ext.part` | 同目录才能原子 rename |
| 备份文件 | 用户选择保存位置，默认桌面 | 单个 `.kithoard-backup.json` |

放 userData 的理由：随 Windows 用户配置漫游、有标准清理策略、不需要管理员权限。不效仿某些工具"把数据放程序目录"，因为安装到 `Program Files` 后普通用户无写权限。

### 5.2 表结构

```sql
-- 素材源注册表：内置元数据，设置页可开关
CREATE TABLE sources (
  id            TEXT PRIMARY KEY,          -- 'pixabay' | 'pexels'
  name          TEXT NOT NULL,
  homepage      TEXT NOT NULL,
  types         TEXT NOT NULL,             -- JSON 数组：["image","video","music","sfx"]
  requires_key  INTEGER NOT NULL DEFAULT 0,
  enabled       INTEGER NOT NULL DEFAULT 1,
  sort_order    INTEGER NOT NULL DEFAULT 0
);

-- 素材元数据：跨源唯一 source_id + remote_id；字段缺失一律 NULL，不填 0
CREATE TABLE assets (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  source_id     TEXT NOT NULL,
  remote_id     TEXT NOT NULL,
  type          TEXT NOT NULL,             -- image|video|audio|sfx|font|template
  title         TEXT,
  page_url      TEXT NOT NULL,             -- 来源页面，署名与"复制链接"用
  thumb_url     TEXT,
  preview_url   TEXT,
  file_ext      TEXT,
  file_size     INTEGER,
  width         INTEGER,
  height        INTEGER,
  duration_ms   INTEGER,
  license       TEXT NOT NULL DEFAULT 'unknown',  -- free|paid|member|unknown
  license_note  TEXT,
  author_name   TEXT,
  author_url    TEXT,
  fetched_at    INTEGER NOT NULL,
  UNIQUE (source_id, remote_id)
);
CREATE INDEX idx_assets_type ON assets(type);

CREATE TABLE favorites (
  asset_id      INTEGER PRIMARY KEY REFERENCES assets(id) ON DELETE CASCADE,
  created_at    INTEGER NOT NULL
);

-- 下载任务：id 用 uuid，允许同一素材下载多次到不同路径
CREATE TABLE downloads (
  id             TEXT PRIMARY KEY,
  asset_id       INTEGER REFERENCES assets(id),
  title          TEXT NOT NULL,
  source_url     TEXT NOT NULL,            -- 解析后的直链
  target_path    TEXT NOT NULL,
  temp_path      TEXT NOT NULL,            -- .part
  total_bytes    INTEGER,                  -- 服务器未给 Content-Length 时为 NULL
  received_bytes INTEGER NOT NULL DEFAULT 0,
  state          TEXT NOT NULL,            -- 见 5.3
  sort_index     INTEGER NOT NULL DEFAULT 0,
  slot           INTEGER,                  -- 占用并发槽位 1..5
  etag           TEXT,                     -- 续传校验
  last_modified  TEXT,
  retry_count    INTEGER NOT NULL DEFAULT 0,
  error_code     TEXT,
  error_message  TEXT,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL,
  finished_at    INTEGER
);
CREATE INDEX idx_downloads_state ON downloads(state, sort_index);

-- 本地素材：以绝对路径为唯一键，和磁盘对账
CREATE TABLE local_files (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  download_id   TEXT REFERENCES downloads(id),
  path          TEXT NOT NULL UNIQUE,
  type          TEXT NOT NULL,
  ext           TEXT NOT NULL,
  size          INTEGER NOT NULL,
  width         INTEGER,
  height        INTEGER,
  duration_ms   INTEGER,
  sha256        TEXT,                      -- 按需计算，用于重复识别
  status        TEXT NOT NULL DEFAULT 'present',  -- present|missing|quarantined
  created_at    INTEGER NOT NULL,
  modified_at   INTEGER NOT NULL
);
CREATE INDEX idx_local_type ON local_files(type);

-- 最近访问网站，只保留 10 条
CREATE TABLE recent_sites (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  url        TEXT NOT NULL,
  title      TEXT,
  visited_at INTEGER NOT NULL
);

-- 设置：扁平 key-value，值存 JSON 字符串
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE schema_meta (version INTEGER NOT NULL);
```

设计取舍说明：

- `assets` 不存"是否已下载"，因为同一素材可能下载多次；关联关系放在 `downloads`/`local_files`。
- `downloads.received_bytes` 与 `.part` 文件的实际大小必须一致，启动恢复时以**磁盘为准**校正数据库，而不是反过来。
- `recent_sites` 不做 UNIQUE 约束而去重时更新 `visited_at`，因为同一站点重复访问要在列表里上浮而不是消失。

### 5.3 下载状态机

状态集合：`queued` / `downloading` / `paused` / `verifying` / `completed` / `failed` / `canceled` / `quarantined`

| 当前 | 事件 | 下一 | 副作用 |
|---|---|---|---|
| — | 入队 | `queued` | 建 `.part`，插入记录 |
| `queued` | 拿到并发槽位 | `downloading` | 发 Range 请求 |
| `downloading` | 用户暂停 | `paused` | 中止请求，保留 `.part`，记录 `received_bytes` |
| `paused` | 用户继续 | `queued` | 重新排到队首 |
| `downloading` | 请求异常 | `failed` | 记录 `error_code`，`.part` 保留 |
| `failed` | 用户重试 | `queued` | `retry_count + 1`；超过 3 次必须人工确认 |
| `downloading` | 字节写完 | `verifying` | 校验大小、魔数、可读性 |
| `verifying` | 校验通过 | `completed` | `.part` 改名为目标名，写 `local_files` |
| `verifying` | 校验失败 | `failed` | `error_code = E_VERIFY_FAILED`，不覆盖任何已有文件 |
| `verifying` | 判定有风险 | `quarantined` | 移入隔离区，`local_files.status = quarantined` |
| 任意未完成态 | 用户取消 | `canceled` | 删 `.part` 与 `.part.meta`（这是临时文件，可删） |
| 任意态 | 软件崩溃 | 启动时校正 | 见 5.4 |

**禁止**：跳过 `verifying` 直接 `completed`；在 `failed` 状态下静默重试而不告知用户。

### 5.4 崩溃恢复规则

启动时扫描 `downloads` 表中 `state in (queued, downloading, paused)`：

1. 以磁盘上 `.part` 的实际大小为 `received_bytes`，修正数据库。
2. `downloading` 一律降级为 `paused`（不知道断点是否写完最后一块）。
3. 若 `.part` 不存在但数据库有记录，标记 `failed` + `E_TEMP_MISSING`，让用户重下。
4. **不自动开始下载**，按需求弹窗询问"是否恢复 N 个未完成任务"。

| key | 类型 | 默认 | 范围 |
|---|---|---|---|

| `download.concurrency` | number | 3 | 1–5 |

## 6. 接口约定

### 6.1 素材源适配器（最核心的扩展点）

需求要求"网络搜索接口应采用可替换的适配器设计"。以下是唯一契约，新接一个源只实现这个文件，不动其他代码。

```ts
// src/main/sources/types.ts
import type { AssetMeta, AssetType } from '../../shared/types'

export interface SearchQuery {
  keyword: string
  type: AssetType | 'all'
  page: number       // 从 1 开始
  pageSize: number   // 固定 20
}

export interface SearchPage {
  items: AssetMeta[]
  page: number
  pageSize: number
  hasPrev: boolean
  hasNext: boolean
  totalKnown: number | null   // 源不提供总数时为 null，UI 不显示"共 N 条"
}

export interface DownloadPlan {
  url: string                 // 直链
  fileName: string            // 建议文件名（不含路径）
  ext: string
  size: number | null
  referer?: string            // 部分 CDN 需要
  headers?: Record<string, string>
}

export interface SourceCapabilities {
  types: AssetType[]
  requiresApiKey: boolean
  attributionRequired: boolean
  maxPageSize: number
}

export interface AssetSource {
  readonly id: string
  readonly name: string
  readonly capabilities: SourceCapabilities

  /** 是否已具备可用条件（key 是否配置等）。未就绪时 UI 灰显而不是搜完报错 */
  isReady(): boolean

  search(q: SearchQuery, signal: AbortSignal): Promise<SearchPage>

  /** 详情页补充字段；搜索结果已够用时可直接返回入参 */
  getDetail(remoteId: string, signal: AbortSignal): Promise<AssetMeta>

  /** 把展示用的预览地址换成真正可下载的直链 */
  resolveDownload(remoteId: string, signal: AbortSignal): Promise<DownloadPlan>

  /** 署名文案；capabilities.attributionRequired 为 true 时必须有返回值 */
  attributionOf(meta: AssetMeta): { text: string; url: string } | null
}
```

约束：

- 适配器**不写数据库**，返回纯对象，由上层统一 upsert。
- 适配器**不发下载**，只解析直链。
- 所有网络调用必须接收 `AbortSignal`，支持用户切页/关窗时中断。
- 不允在适配器里 catch 后返回空数组。异常向上抛，由 `ipc/guard` 转 `AppError`。

### 6.3 错误信封与错误码

所有 IPC 统一返回 `{ ok: true, data } | { ok: false, error: AppError }`，不让 Electron 的原始异常穿过 IPC（会丢失结构）。

```ts
// src/shared/errors.ts
export type ErrorCode =
  | 'E_NETWORK'          // 网络不可达/超时
  | 'E_RATE_LIMITED'     // 429，已含退避后仍失败
  | 'E_SOURCE_DOWN'      // 源服务异常 5xx
  | 'E_AUTH_REQUIRED'    // 需要登录，按红线不绕过
  | 'E_LICENSE_UNKNOWN'  // 许可不明，禁止下载
  | 'E_LICENSE_PAID'     // 付费/会员专享，禁止下载
  | 'E_UNSUPPORTED'      // 该源不支持此类型
  | 'E_DISK_FULL'        // 磁盘写失败
  | 'E_DIR_UNWRITABLE'   // 目标目录不可写
  | 'E_VERIFY_FAILED'    // 大小/格式/可读性校验不通过
  | 'E_TEMP_MISSING'     // 续传时 .part 丢失
  | 'E_FILE_IN_USE'      // 文件被占用
  | 'E_FFMPEG_MISSING'   // 找不到 ffmpeg 二进制
  | 'E_MEDIA_UNSUPPORTED'// 媒体格式不支持
  | 'E_RISK_FILE'        // 判定有风险，已隔离
  | 'E_RESTORE_INVALID'  // 备份文件不合法
  | 'E_UNKNOWN'
```

`AppError` 额外带 `retryable: boolean`（决定 UI 是否显示"重试"按钮）与 `detail?: string`（仅用于"查看详情"，默认折叠）。文案在 `errors.ts` 里做中文映射，**不允许把英文原始报错直接甩给用户**。

### 6.4 命名与字段规范

- TypeScript：`camelCase` 变量/函数，`PascalCase` 类型，常量 `SCREAMING_SNAKE`。
- 数据库：`snake_case` 列名，表名复数。
- 时间统一存 **Unix 毫秒整数**，不存字符串。
- 字节数统一用 `bytes` 后缀命名，不混用 MB。
- 布尔字段统一 `is/has/can` 前缀或 `enabled` 这类形容词，不出现 `flag1`。

## 7. 开发顺序与验收口径

### 7.1 总顺序

严格按依赖顺序推进，每个版本结束时软件**必须可启动、可用**，不允许出现"这版先跑不起来，下版一起修"。

| 顺序 | 版本 | 主题 | 前置依赖 |
|---|---|---|---|

### 8.1 署名展示（原"卡片不显示来源"冲突）

**结论**：卡片底部加一行 11px 灰字署名；详情页显示完整署名（作者名 + 来源站名 + 回链，回链按源的要求带 `utm` 参数）。**卡片仍不显示来源网站图标和名称**——"不显示图标"和"必须署名"是两件事，不冲突。

**理由**：

- Unsplash API 指南要求展示照片时必须标注 Unsplash 与摄影师并回链主页，链接需带 `utm_source=你的应用名&utm_medium=referral`。
- Pexels 要求尽可能标注摄影师（"Photo by XX on Pexels"）并链接到图片页；申请无限调用配额时，署名是审核条件之一。
- Pixabay 按 Pixabay License 不强制署名，但官方 API 要求缓存响应 24 小时、不建议直接热链。
- 若卡片完全不显示任何来源信息，可选源会被压缩到只剩 Pixabay 一家，多源架构失去验证样本。

**落地要求**（V0.1.0 必须做完，即使首版只接 Pixabay）：

1. `assets` 表保留 `author_name` / `author_url`（见 5.2，已建好）；
2. 适配器实现 `attributionOf()`，并用 `capabilities.attributionRequired` 声明是否强制；
3. 卡片组件留出署名插槽，`attributionRequired === false` 时不渲染（首版 Pixabay 属于这种）；
4. 详情页无条件预留完整署名区，数据为空时显示"来源信息未提供"，不留白也不隐藏。

**若将来推翻**：接 Unsplash / Pexels 前必须重新评估合规性，不做"先接上再说"。

### 8.2 首版素材源与素材类型

**结论**：

1. 首版只接 **Pixabay 单源**，覆盖**图片与视频**两类。
2. **模板类不做**，界面该分类置灰并写明"暂不支持"，不出假结果。
3. 音乐、音效、字体不在首版，等接口可用性核实后按版本追加。
4. Pexels 作为第二个源进 **V0.3.0**，用途是验证多源适配架构与设置页的源开关，不是扩内容。

**理由**：

- 六类素材里只有部分有合法公开接口：图片/视频（Pixabay、Pexels、Unsplash 确定）、音乐/音效（Pixabay，开放程度需以官方文档为准）、字体（Google Fonts Developer API，但语义是"字体下载站"不是"素材搜索"）、设计模板（**没有可用公开接口，确定没有**）。
- 首版的价值是验证"搜索 → 下载 → 管理"这条链路能否跑通，不是比内容多少。单源让故障面最小。

**落地要求**：V0.1.0 的类型筛选器直接按"图片 / 视频 / 其余置灰"三态实现，不要先做六类再删。置灰项必须带 `disabled` 属性与提示文案，不能是"点了没反应"的死按钮。

### 8.3 "免费/付费/会员专享"字段（随附确认：保留）

**结论**：字段保留，首版全部显示"免费/可下载"，不为付费分支做复杂交互。

**理由**：该字段是"阻止下载"逻辑的承载点——`license !== 'free'` 时禁用下载并提示，未来接任何源都用得上；但首版所接源全为免费素材，字段恒为"免费"，因此不为它堆 UI。

**落地要求**：详情页按 `license` 四态渲染（free / paid / member / unknown），只有 `free` 可下载，其余禁用并说明原因；**不做"付费后即可下载"的任何引导**。

### 8.4 卸载与用户素材（原"卸载时删除下载素材"）

**结论**：卸载**默认保留**素材与数据库，只删程序本体；另给勾选项"同时删除我下载的素材"并**二次确认**；确认页必须列出将被删除的绝对路径清单。

**理由**：

1. 素材是用户花时间挑的，卸载应用顺手删掉几十 GB 会引发强烈不满。
2. 与既有的"永不永久删除任何文件"原则直接冲突。
3. 默认下载目录在 `Pictures/Kithoard`（用户文档区），若用户把下载目录改成 `D:\素材` 甚至盘符根目录，卸载器无条件删除的后果不可控。

**落地要求**：卸载器只用 NSIS 内置指令处理**应用自有目录**；用户素材目录仅在被勾选时按清单逐个删除，且清单必须在执行前展示。**这是 2.2 节"删除走回收站"的唯一例外**——安装器运行时无法调用 `shell.trashItem`，因此必须用二次确认 + 路径清单 + 默认不勾选三重保障来替代回收站。

### 8.5 诊断日志（原"不记录独立运行日志"）

**结论**：写轮转诊断日志到 `%APPDATA%/Kithoard/logs/`，单文件 2 MB × 3 份；**不提供任何 UI 入口**（设置页不出现"日志"字样，也不出现"查看日志"按钮）。

**理由**：需求四的"不记录独立运行日志"应理解为"不向用户暴露日志功能"，而非禁止排障所需的诊断信息。需求同时要求"下载失败显示原因"，若磁盘上不留痕迹，用户报障时只能复述现象，排障成本极高。

**落地要求**：只记错误与关键状态迁移；不记用户搜索关键词、不记完整 URL 查询串（隐私）；写满 3 份后覆盖最旧，不做无限增长。

### 8.6 缓存 7 天清理范围（原"缓存指什么"）

**结论**：7 天自动清理**只针对** `%APPDATA%/Kithoard/cache/`（缩略图、预览图、素材源 API 响应缓存）；**`.part` 临时文件永不参与任何自动清理**。

**理由**：`.part` 是未完成任务的续传基础，清掉等于毁掉用户已下载的进度；缩略图与接口响应缓存清了只是重新拉一次，无损失。Pixabay 要求响应缓存 24 小时，7 天清理窗口不违反该要求。

**落地要求**：清理逻辑使用目录白名单硬编码，不允许"扫描 userData 下的大文件"这类宽松规则；每次清理后写一条诊断日志。

### 8.7 内嵌浏览（随附确认：V0.6.0 用 WebContentsView 做只读浏览）

**结论**：用 `WebContentsView` 实现站内浏览，功能边界为：地址栏、前进/后退、刷新、复制当前链接、外部打开、最近访问 10 条；拦截新窗口弹窗；页面内下载改由本应用接管；遇到登录墙提示用户在系统浏览器打开，**不代填账号密码**。

**理由**：

- 需求二.2 明确要求"软件内部浏览素材网站"，不能砍。
- 大量站点用 `X-Frame-Options` / CSP `frame-ancestors` 禁止被 iframe 嵌入；`WebContentsView` 不是 iframe，不受此限制，且是 Electron 官方推荐的多页面组合方式。
- 内嵌浏览涉及 Cookie 隔离、下载拦截、弹窗处理，安全面大，所以放 V0.6.0，并在架构上隔离为 `browser` 单一模块（见 4.3），便于将来换栈时整体替换。

### 8.8 安全扫描能力边界（随附确认：本地静态检查先行）

**结论**：V0.6.0 只做本地静态检查——扩展名白名单、文件魔数校验、可执行/脚本类拦截、大小与可读性校验；文案明确写"本检查不等同于杀毒软件"。调用 Windows Defender 命令行（`MpCmdRun.exe`）列为 V1.1.0 的可选增强，**且调用失败不得阻断下载主流程**。

**理由**：不引第三方杀毒引擎（体积与授权都不现实）；`MpCmdRun.exe` 的路径与参数在不同 Windows 版本上不一致，未做真机验证前不能写成硬依赖。

### 8.9 API Key 来源

**结论**：用户在设置页自行填写 Key，应用提供申请链接与图文说明；**不内置任何 Key，也不自建代理中转**。

**理由**：内置 Key 硬编码在安装包里可被提取，且配额（Pixabay 约 100 次/分钟）会被所有用户共享、很快耗尽；自建中转等于承担代理服务与合规责任，超出本项目范围。

**落地要求**：首启引导说明申请方式；Key 未配置时对应源显示"未配置"而不是搜索时报错；Key 只存本地 `settings` 表，不上传。

### 8.10 需求内部矛盾的处置（随附确认）

| 位置 | 矛盾 | 处置 |
|---|---|---|
| 收藏夹节 vs 优先级 | 收藏夹写"数据支持手动备份和恢复"，但第一阶段未列备份 | 收藏与备份都在 V0.3.0 交付 |
| 本地素材 vs 优先级 | 第三阶段提"重复文件识别"，九节验收未提 | 首版不做；V1.1.0 用 `sha256` 做"同内容提示"，只提示不自动删 |
| 下载管理 vs 设置 | "不记录独立运行日志"与"下载失败显示原因" | 见 8.5：写轮转日志但不暴露入口 |

- 音频截取
- 图片基础编辑
- 软件设置

这不是一个网页演示项目，也不是静态 UI 原型，而是一个需要真实运行的桌面应用程序。

### 二、开发要求

1. 先检查当前开发环境。
2. 先搭建项目结构。
3. 先完成软件主界面。
4. 再开发核心业务功能。
5. 每完成一个模块都进行测试。
6. 不要一次性生成大量未经测试的代码。
7. 不要使用虚假数据冒充真实网络搜索结果。
8. 不要使用虚假的下载进度。
9. 网络接口必须采用可替换架构。
10. 对没有合法访问接口的网站，明确显示暂不支持，不得绕过网站限制。

### 三、技术方案

优先考虑：

- 桌面框架：Tauri 2 或 Electron。
- 前端：React + TypeScript。
- UI：现代化组件化设计。
- 本地数据库：SQLite。
- 文件处理：根据实际需要使用可靠的本地处理工具。
- 视频、音频处理：可评估 FFmpeg。
- 图片处理：采用成熟的图片处理库。
- 下载：采用支持暂停、恢复和断点续传的下载模块。

请先根据开发环境判断最合适的技术组合，并解释选择原因。

### 四、界面设计

整体采用现代化 Windows 桌面软件风格。要求：

- 右侧主内容区域。
- 首页突出搜索框。
- 素材卡片统一设计。
- 支持窗口缩放。
- 页面简洁、清晰，不要堆砌功能。

- 不要设计无实际功能的按钮。

第一阶段：先完成主窗口、导航、首页、搜索框、素材卡片、分页、素材详情、收藏夹和 SQLite 数据结构。

### 六、必须遵守的规则

- 搜索结果每页默认 20 条。
- 支持传统分页。
- 下载并发数 1 至 5。
- 支持批量下载。
- 批量下载前显示文件数量和预计占用空间。
- 支持暂停、继续、取消下载。
- 支持断点续传（服务器允许时）。
- 软件启动时询问是否恢复未完成任务。
- 下载完成后提供打开文件和打开文件夹。
- 本地素材列表默认统一列表视图。
- 所有危险删除操作必须二次确认。
- 压缩替换原文件前必须确保新文件处理成功。
- 不允许绕过网站登录、会员、付费或下载限制。
- 对授权不明的素材进行风险提醒并阻止下载。
